17/08 — Causa Raiz Confirmada
Entendemos o que ocorreu: iMile parou de enviar novidades por push (mecanismo principal) entre 12–16/jun, devido a instabilidade sistêmica. O backup não recuperou os eventos finalizadores (entrega/incidência) — os pacotes ficaram "em aberto" e entraram no fluxo de demora, gerando pagamento de BPP.
Causa Raiz — Dupla Falha

⚙️ Falha Interna (Meli)

O monitoramento não reemitiu o alerta do problema — a lógica de monitoramento tratou o período de instabilidade como estável.

🚚 Falha iMile

Não identificou que só recebíamos updates via job (mecanismo de backup), nem reportou proativamente a queda das APIs de push.

Mecanismo do problema: push (canal principal de novidades) indisponível entre 12–16/jun → job de backup ativo, mas sem recuperar eventos finalizadores (entrega/incidência) → pacotes permanecem "em aberto" no sistema → entram no fluxo de demora → geram pagamento de BPP ao buyer mesmo quando o status real já poderia estar resolvido.
